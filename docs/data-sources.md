# Data Sources

This document describes the origin, preparation, normalization, review decisions, and licensing considerations for the food composition dataset used by nutrition-app.

The application does not consume third-party composition tables directly at runtime. Instead, it uses a reviewed and reproducible CSV generated inside the project from immutable source material and explicit project-level decisions.

## Final dataset

The final application dataset is stored at:

```text
database/data/foods/taco-v4.csv
```

It contains 592 food records.

Each record exposes only the fields required by the current nutrition-app domain:

```text
source_code
name_pt
name_en
calories_per_100g
protein_per_100g
carbs_per_100g
fat_per_100g
```

The generated CSV must not be edited manually.

It is regenerated with:

```bash
php scripts/prepare_taco_csv.php
```

The preparation process combines:

```text
database/data/foods/taco-composicao-brolesi.csv
database/data/foods/taco-v4-overrides.csv
```

to generate:

```text
database/data/foods/taco-v4.csv
```

## Primary scientific source

The primary scientific source is:

> Tabela Brasileira de Composição de Alimentos - TACO
> 4th revised and expanded edition
> Núcleo de Estudos e Pesquisas em Alimentação - NEPA
> Universidade Estadual de Campinas - UNICAMP
> Campinas, 2011

Official publication:

* https://nepa.unicamp.br/publicacoes/tabela-taco-pdf/
* https://nepa.unicamp.br/publicacoes/tabela-taco-excel/

The original fourth-edition dataset contains 597 food records.

The project preserves the original TACO food codes through the `source_code` field so that generated records remain traceable to their source entries.

## Technical processing source

The normalized source CSV used by the project was derived from the open-source repository:

> brolesi/taco
> Fabio Fogliarini Brolesi

Repository:

* https://github.com/brolesi/taco

The repository provides scripts and structured files derived from the official TACO spreadsheet.

The nutrition-app project uses this processing work as a technical starting point. The repository is not treated as the scientific authority for the nutritional values.

The distinction is:

```text
TACO / NEPA / UNICAMP
Scientific source of the food composition data.

brolesi/taco
Technical source used to extract and structure the official spreadsheet.
```

The copied normalized source file is stored at:

```text
database/data/foods/taco-composicao-brolesi.csv
```

This file is treated as immutable project source material.

Project-specific corrections, complementary values, normalizations, and exclusions are not applied directly to this file.

## Reproducible preparation

The final dataset is generated by:

```text
scripts/prepare_taco_csv.php
```

The script:

1. reads the immutable normalized TACO source;
2. validates the required source columns;
3. reads and validates project override decisions;
4. verifies that every declared decision references an existing TACO code;
5. applies reviewed nutritional overrides;
6. excludes reviewed records marked for removal;
7. normalizes documented source artifacts;
8. writes the simplified nutrition-app CSV;
9. reports generation totals.

The expected generation summary is:

```text
Generated 592 records.
Overridden records: 10.
Removed records: 5.
Records with empty calories: 0.
```

## Preserved source behavior

Whenever possible, source values are preserved exactly as represented in the normalized input.

The preparation process preserves:

* original food codes;
* Portuguese food descriptions;
* decimal precision;
* empty fields unless explicitly resolved;
* positive scientific notation such as `1e-05`;
* source row identity.

The value:

```text
1e-05
```

represents a positive trace quantity and must not be converted to zero.

English names are intentionally left empty in the current dataset:

```text
name_en
```

They may be added later through a separate reviewed translation dataset.

## Negative carbohydrate normalization

The normalized TACO source contains a small number of negative carbohydrate values.

These values originate from the source calculation by difference and have no practical nutritional meaning for the application.

For source records without an explicit override, negative carbohydrate values are normalized to:

```text
0
```

Empty values are not automatically converted to zero.

The distinction is:

```text
Negative numeric value
Source calculation artifact that may be normalized according to a documented rule.

Empty value
Unknown or unavailable information that requires review, a complementary source, or removal.

Positive scientific notation
A trace positive quantity that must be preserved.
```

## Project override decisions

Project-specific decisions are stored at:

```text
database/data/foods/taco-v4-overrides.csv
```

This file is the declarative source for:

* nutritional overrides;
* reviewed zero substitutions;
* record removals;
* complementary data references;
* human-readable decision notes.

The preparation script does not contain hard-coded food codes for these decisions.

Supported actions are:

```text
override
remove
```

### Override

An `override` preserves the original:

```text
source_code
name_pt
name_en
```

and replaces only:

```text
calories_per_100g
protein_per_100g
carbs_per_100g
fat_per_100g
```

### Remove

A `remove` decision prevents the source record from being written to the final CSV.

## Oil normalization decisions

The official TACO spreadsheet reports protein and carbohydrates as `NA` for the following oils:

| TACO code | Food                           |
| --------- | ------------------------------ |
| 259       | Azeite, de dendê               |
| 260       | Azeite, de oliva, extra virgem |
| 267       | Óleo, de babaçu                |
| 268       | Óleo, de canola                |
| 269       | Óleo, de girassol              |
| 270       | Óleo, de milho                 |
| 271       | Óleo, de pequi                 |
| 272       | Óleo, de soja                  |

For these entries, TACO reports:

```text
884 kcal
NA protein
NA carbohydrates
100 g lipids
```

For the nutrition-app data model, these reviewed non-applicable macronutrient values are represented as:

```text
884 kcal
0 g protein
0 g carbohydrates
100 g fat
```

These substitutions are explicit overrides. They are not the result of a generic rule that converts every `NA` value to zero.

The project intentionally does not implement a global:

```text
NA -> 0
```

conversion.

Each substitution must be reviewed according to the meaning of the source field and the requirements of the application domain.

## Complementary TBCA data

Two TACO records with incomplete composition data were complemented with values from:

> Tabela Brasileira de Composição de Alimentos - TBCA

Official website:

* https://www.tbca.net.br/

### TACO 457

```text
TACO code: 457
TACO description: Leite, de vaca, desnatado, UHT
TBCA reference: BRC0070G
```

Values used per 100 g:

```text
Calories: 39 kcal
Protein: 2.98 g
Carbohydrates: 5.95 g
Fat: 0.36 g
```

The TBCA reference corresponds to skimmed UHT cow's milk.

### TACO 458

```text
TACO code: 458
TACO description: Leite, de vaca, integral
TBCA reference: BRC0044G
```

Values used per 100 g:

```text
Calories: 65 kcal
Protein: 2.35 g
Carbohydrates: 7.16 g
Fat: 3.04 g
```

The TBCA reference corresponds to an average of whole UHT cow's milk samples.

The TBCA values are stored exactly as reviewed in:

```text
database/data/foods/taco-v4-overrides.csv
```

They must not be silently recalculated, replaced, or presented as original TACO values.

## Removed records

Five original TACO records are excluded from the final dataset.

### TACO 450 - Iogurte, sabor abacaxi

Reason:

```text
Incomplete composition and no reliable complementary source was found.
```

No sufficiently specific and reliable complementary source was found for the exact food.

### TACO 472 - Cana, aguardente 1

Reason:

```text
Calories exist, but all macronutrients used by nutrition-app are absent in TACO.
```

The record contains caloric energy but does not provide the protein, carbohydrate, or lipid values required by the current application model.

Because the application stores calories and these three macronutrients, the record was removed instead of converting unavailable source values into inferred zeros.

### TACO 516 - Sal, dietético

Reason:

```text
Food with 0 kcal and no practical use for caloric equivalence.
```

This record is not useful for the calorie-equivalence behavior of the MVP.

### TACO 517 - Sal, grosso

Reason:

```text
Food with 0 kcal and no practical use for caloric equivalence.
```

This record is not useful for the calorie-equivalence behavior of the MVP.

### TACO 591 - Coco, verde, cru

Reason:

```text
Incomplete composition and no reliable specific source for raw green coconut was found.
```

Sources describing generic raw coconut or coconut water were not considered equivalent to the specific TACO entry for raw green coconut.

The record was removed instead of receiving values from a different food.

## Scope and limitations

This dataset is designed for the current nutrition-app MVP.

It is not intended to be:

* a complete reproduction of TACO;
* a complete reproduction of TBCA;
* a medical or clinical nutrition database;
* a substitute for professional nutritional guidance;
* a guarantee that every food product matches every commercial formulation;
* an authoritative source for nutrients not stored by the application.

The current application stores only:

```text
calories
protein
carbohydrates
fat
```

Other components present in the original scientific tables are intentionally excluded.

Food composition values may vary according to:

* brand;
* cultivars;
* production process;
* preparation method;
* sampling;
* laboratory method;
* regional differences;
* publication updates.

## Future changes

Any future dataset change must remain reproducible.

New corrections should:

1. preserve the immutable source CSV;
2. be recorded in the overrides CSV;
3. identify the scientific or technical source;
4. include a clear decision note;
5. be covered by validation or automated tests;
6. regenerate the final CSV through the preparation script;
7. update this document when the source history or licensing implications change.

Manual edits to:

```text
database/data/foods/taco-v4.csv
```

must not be used as the permanent source of a correction.
